# Океан — учебный план из план-сетки

Одностраничное приложение для XLSX-планов смен. Читает мероприятия, предлагает распределение по разделам и модулям, считает академические часы и заполняет таблицу 1.2.1 в копии DOCX-шаблона. Остальные части документа остаются исходными. Информационная карта и содержание программы в этой версии не заполняются.

## Запуск

Требуется Node.js 20 или новее. Установка пакетов не нужна.

```sh
node scripts/server.mjs
```

Открыть http://127.0.0.1:4173. Загружать XLSX через поле выбора файла. Лист и программа выбираются независимо. Изменение источника сбрасывает текущий разбор.

```sh
node --test tests/core.test.mjs
node scripts/build.mjs
```

Папка `dist/` содержит готовый статический сайт. Поддерживается размещение в подкаталоге GitHub Pages. Приложение использует только относительные пути. Нужен HTTP-сервер, открытие `index.html` через `file://` не поддерживается.

## Работа с приложением

1. Загрузить XLSX или попробовать загрузку публичной Google Таблицы по ссылке.
2. Выбрать лист и программу, нажать «Разобрать план-сетку».
3. Проверить неизвестные мероприятия и неоднозначное время. Одинаковые названия в одном разделе объединены в карточку: показаны число занятий на ребёнка и все исходные записи. Раздел, название и общую длительность можно подтвердить сразу для всех повторов. Дату, ячейку, время и отдельное проведение можно проверить через «Все исходные записи».
4. Галочка «Применить раздел и длительность ко всем мероприятиям с таким названием» переносит выбранный раздел и введённую длительность на все записи с исходным названием, включая другие разделы и записи, требующие уточнения. Введённое время подтверждается; число проведений и исключение у остальных записей сохраняются. Без галочки изменения касаются только открытой записи или показанной группы. Если поле длительности пустое, исходное время и статус его проверки сохраняются; 0 минут применяется как явное значение.
5. Проверить итог по разделам. Перед скачиванием обязательно открывается окно распределения. Экспорт недоступен, пока не проверены все включённые записи.
6. Скачать DOCX. Исходные файлы не изменяются.

Число часов в примере не является контрольным итогом. Расчёт ведётся на одного ребёнка; проведения одного занятия для разных отрядов и подгрупп не суммируются между собой.

## Правила расчёта

- Академический час — 40 минут. Каждое проведение округляется вверх отдельно; после округления часы умножаются на количество занятий, посещаемых одним ребёнком, и суммируются по названию и разделу.
- Явно заданные при проверке 0 минут = 0 часов. Мероприятие остаётся в документе. Пустое или неизвестное время не считается нулём и требует проверки.
- 60 минут = 2 часа; два интервала по 40 минут с перерывом = 2 часа.
- Для объединённых ячеек берётся сумма интервалов столбца «время», без промежутков. Пересекающиеся интервалы в одной ячейке объединяются.
- Явное время в тексте имеет приоритет над общим временем сетки. Если внутри явно заданного интервала перерывы не указаны, требуется проверить их вручную.
- `(3 отр.)` означает третий отряд, не три проведения. `(1, 2 отр.)` означает два отряда, но одно занятие на ребёнка. Пометки `1 гр`, `2 гр.`, `1 группа`, `2 подгруппа` распознаются с точкой и без, в скобках и вне их. Поддерживаются списки и диапазоны номеров.
- Повторы курса считаются отдельно по каждому отряду и подгруппе за всю смену, в том числе при чередовании дат. Общие занятия добавляются всем. При разной нагрузке выводится предупреждение и учитывается максимальная нагрузка на ребёнка; все исходные проведения можно исправить вручную.
- Параллельные события в одной ячейке автоматически получают время слота только при явно указанных непересекающихся списках отрядов или подгрупп.
- При нескольких интервалах для разных отрядов, неоднозначном количестве или отсутствии времени запись требует подтверждения. Пользователь задаёт длительность одного проведения и число проведений.
- Идентичное событие с тем же явным интервалом в тот же день в соседних записях помечается исключённым дублем; исключение можно отменить. Разные отряды в исходном тексте не считаются дублями.
- Переносы строк и разделитель ` / ` разбивают ячейку на события. Сокращения `Д/д`, `О/д` не разбиваются. Сложные формулировки через запятую остаются одной записью для проверки пользователем.
- Названия нормализуются по регистру, кавычкам, пробелам и пунктуации. Близкие, но разные названия автоматически не объединяются.

## Справочники и шаблоны

В `public/assets/` находятся копии исходного шаблона, календарного плана и примера. Их можно заменить через интерфейс на текущий сеанс либо заменить файлы в репозитории и пересобрать сайт.

Точное совпадение из примера имеет приоритет перед календарным планом. Неоднозначные совпадения и похожие названия предлагаются только для ручного выбора. Мероприятия из справочников не добавляются в сетку. Список модулей извлекается из выбранного шаблона.

Поддерживаемый шаблон: таблица «Общая трудоёмкость» с разделами 1, 2, 3, модулями 3.x и досуговой деятельностью; две строки заголовка; 7 колонок; хотя бы одна пустая строка без объединений. Выход сохраняет таблицу, сетку колонок и заголовки, заново заполняет строки мероприятий и итоги. Номера разделов и мероприятий записываются текстом, автоматические списки Word в новых строках отключены, включая наследование из стиля. Теория, практика, формы контроля и образовательный продукт остаются пустыми. Пустые модули сохраняются с прочерками. Остальные таблицы, стили и части DOCX не изменяются.

Поддерживаемая план-сетка: строка заголовков со столбцом «время», даты в B, программы справа, «МП» — вспомогательные столбцы. Поддерживается XLSX с общими строками, встроенными строками и объединёнными ячейками. Формулы читаются по сохранённым значениям, не пересчитываются. XLS, CSV и произвольные форматы сетки не поддерживаются.

Календарный план читается по таблицам с номером модуля и описанием, содержащим «Цель:». Для иного формата потребуется адаптация парсера.

## Данные и ограничения

Загруженные файлы обрабатываются в браузере, не отправляются на сервер и не сохраняются между перезагрузками страницы. Вкладку следует держать открытой до скачивания результата. Код не использует внешние шрифты, аналитику или CDN. Вендорный JSZip поставляется с лицензией.

Прямая загрузка Google зависит от доступа к файлу и политики CORS Google. Если запрос заблокирован, приложение предлагает ссылку скачивания XLSX. Импорт через XLSX — основной проверенный путь. Google OAuth и серверный прокси в первой версии отсутствуют.

В публичную сборку входят только исходные DOCX из `public/assets/`; загруженные пользовательские XLSX не включаются. Перед публикацией следует учитывать доступность встроенных справочников посетителям сайта.

## GitHub Pages

Workflow `.github/workflows/pages.yml` запускается вручную. В репозитории нужно выбрать Settings → Pages → Source → GitHub Actions, затем запустить workflow «Deploy GitHub Pages». Сборка публикует только `dist/`. Изменения должны предварительно попасть в GitHub; разработка сама по себе ничего не публикует.

## Интеграционная проверка

Поместить исходную сетку в `.local/plan.xlsx`, запустить `node scripts/server.mjs --test`, открыть `/__test/`. Тест проверяет реальную сетку, модули, перерывы, параллельные отряды, повторы, сохранность исходных частей DOCX и пустые колонки. Тестовый DOCX содержит только готовые записи и не является полным учебным планом. Тестовые маршруты работают исключительно с флагом `--test`, не попадают в `dist/`.

Проверено после исправлений: 20 модульных тестов; интеграционный прогон на исходной сетке; импорт и ручное распределение в браузере; запрет скачивания при незавершённой проверке. Проверены нулевые часы в DOCX и отключение автонумерации во всех новых ячейках. Структура экспортированного DOCX проверена, все части пакета кроме `word/document.xml` сохранены побайтово. Визуальная проверка страниц DOCX не выполнена: в среде отсутствует LibreOffice. Перед рабочим использованием следует проверить переносы и разбиение таблицы на страницы в Word.

Для автоматической проверки интерфейса: запустить сервер с `--test`, затем `node tests/ui.mjs`. Нужны Playwright и Chrome; если Playwright доступен вне проекта, указать путь к его `index.mjs` в переменной `PLAYWRIGHT_MODULE`. Сценарий использует `.local/plan.xlsx` для интеграционного прогона и синтетическую сетку для проверки повторов, подгрупп, нулевых часов и экспорта. Результаты проверки сохраняются в `.local/`.
